Flex-VecPool: Flexible SPM Partitioning on Vectorized MemPool

SystemVerilog Computer Architecture Many-Core Optimization

The Challenge: Bandwidth Wall

Modern many-core SoCs increasingly hit an interconnect-bandwidth wall once hundreds of vector units stream data from a shared scratch-pad memory (SPM). This creates a bottleneck that limits performance even when ample compute power is available.

The Solution: Flex-VecPool

This thesis introduces Flex-VecPool, which confronts this challenge by fusing the run-time address-scrambling engine of Flex-TeraPool with the vectorised core clusters of MemPool-Spatz. The result is a fully software-transparent SPM that can be repartitioned to favour locality within each tile.

Hardware Implementation

The added hardware consists of a lightweight, configurable remapper on every memory port. Synthesis in GF-12 nm shows a total cell-area increase below 1% (0.71% on MemPool, 0.99% on TeraPool), with the largest delta confined to the address cross-bar.

Performance Results

Benchmarking four kernels across three system sizes (4–128 cores) demonstrates that locality-aware folding delivers large, workload-selective gains.

  • Dot Product: Speed-ups reach 4.6× on a 128-core TeraPool and 69% fewer cycles on a 64-core MemPool.
  • GEMV: Up to a 66% cycle reduction.
  • Impact: FPU-utilisation jumps from 5% to 22% for Dot Product and from 12% to 36% for GEMV on large clusters.

Conclusion

Overall, Flex-VecPool shows that a < 1% area investment in dynamic SPM partitioning can unlock multi-fold performance gains for bandwidth-dominated, sequential workloads without modifying existing software, and it scales seamlessly from MinPool up to the large TeraPool system.
